# Helix Reborn Design Document

## What is Helix

[Helix](https://github.com/Biomaterials-for-Medical-Devices-AI/Helix) is a streamlit app that is published as PyPI package. It is meant to run locally on a user's machine like a desktop app. Its job is to build and evaluate machine learning (ML) models. More information can be found in the [Helix's docs](https://biomaterials-for-medical-devices-ai.github.io/Helix/index.html). Helix covers the lifecycle of model development from EDA, to data clearning, to training and evaluation.

## The future of Helix

The current form is a spoof of a desktop app. There are docs to explain how to use it, but this could be a better experience as a web app. This would allow for multiple users and auth. An API would allow for programmatic triggering of model training and evaluation. It would allow an easier way to find and download generated graphs, cleaned data and models.

Hosting the app online also means users don't have to worry about having the right hardware to train models because helix will provide it.

Ultimately this will still be the no code solution to model training and evaluation that old helix is.

## The stack

The app will have a React + Next.js frontend, a C#/.NET API, a postgres database, keycloak for auth, Python microservices to handle the actual helix functionality (EDA, data cleaning, model training and evaluation).

The app will be hosted on DigitalOcean and use terraform as IaC.

## The Python bits

This will be influenced by the old app. Some of it can be lifted and some of it will change in this new version.

One big thing I always wanted to introduce in the old one was the use of Sci-kit Learn `Pipeline`s. I wanted the process things like scaling and filtering the data to be combined with the model training. So the idea is that the user is building their own training pipeline. Once that's built, then do the evaluation.

The Python processes should exist as microservices. One for the training pipeline and one for the evaluation. There should be a third which is for the EDA stuff.

The models that are produced should all be Onnyx compatible, which may mean some models can't be ported, but that is an acceptable loss. A big point around this is reusability of models. Onnyx is supported by many programming languages.

The microservices can all be containerised with Docker.

I would like to use `uv` for package management. Also, I'd like to use `ruff` for all the linting and formatting. The code will have type annotations for function signatures. It will use Google style docstrings.

## The frontend

The old app has numbered pages that correspond to the order of operations in the pipeline. The preprocessing and training can probably be merged since they will form the training pipeline.

There will need to a landing page with a button to sign in (auth by keycloak). I would like the app to be sign-up by invitation only, like resource-provisioner.

There will need to be a page where users can view their experiments. They can see the pipelines they created and any graphs they've produced.

There should be a page where users can use their trained models to make predictions against new data.

## The API

This will be responsible for communicating to the Python microservices what needs to be done. The model training service will need to read of a queue, so the API will enqueue jobs for that ervice to consume, which in turn will report back to the API when a job is finished.

The API will also be in charge of finding the images and files generated by the Python jobs (which will go to DO Spaces) and serving them to users upon request.

## User journey

1. An invited user signs in to helix.
2. They create an experiment.
3. (Optional) They perform EDA.
4. They create a training pipeline, which may optionally have a pre-processing step.
5. They run the training pipeline.
6. They can then evaluate the model that comes out.

At the end, they can go back and look at the experiments they've created and even use their model on new data. If they want, they can download the graphs, Onnyx and other files associated with an experiment.
