# Web app

The Next.js frontend in `web/`: a public landing page, sign-in, the signed-in app shell, experiments and the admin
Users page.

## Running it

To run it in Docker with the rest of the app, see [local-development.md](local-development.md); the image is built by
`web/Dockerfile`. To work on it, from `web/`, with Node 22 and Corepack enabled (`corepack enable`), so you get the npm
version pinned in `package.json`:

Copy `.env.example` to `.env.local` and fill in `AUTH_SECRET` and `AUTH_KEYCLOAK_SECRET` first (see
[auth-setup.md](auth-setup.md#client-secrets)). The landing page, sign-in and `/api/health` work without the API or
Keycloak; everything else needs Keycloak (`docker compose up -d` from the repo root) and, for anything that calls the
API, the API too.

```bash
npm install          # also installs the Husky pre-commit hook
npm run dev          # http://localhost:3000
npm run lint         # ESLint, including Prettier and import order
npm run format       # Prettier --write
npm test             # Vitest, once
npm run build        # production build to .next/standalone
```

The pre-commit hook runs `lint-staged`: `eslint --fix` on staged TS/JS files and Prettier on JSON, CSS and Markdown.

## Public pages

`/`, `/sign-in` and `/api/health` are reachable without a session (`PUBLIC_PATHS` in `lib/auth/authorized.ts`).
`proxy.ts`'s matcher also excludes `api/auth` and static assets, so Auth.js's own endpoints and the health check never
hit the `authorized` callback. Every other page redirects a signed-out visitor to `/sign-in`; `/api/proxy/*` answers
401 instead.

The landing page (`app/page.tsx`) reads the session with `auth()` inside a `<Suspense>` boundary (required with
`cacheComponents`) and redirects a signed-in visitor to `/experiments`; otherwise it renders a hero with a "Sign in"
button that posts to the same `signInWithKeycloak` server action as `/sign-in`.

`GET /api/health` always answers 200 with `{ status: "ok", version, api }`: `version` comes from `HELIX_VERSION`
(`"dev"` when unset), and `api` is the API's own `/health` response (fetched with a 3 second timeout) or `null` when
the API is unreachable. The deploy workflow (#44) polls it through the public URL and compares `version` and
`api.version` against the image it just deployed.

## Sign-in and the session

Auth.js v5 signs users in with Keycloak; [auth-setup.md](auth-setup.md#client-settings) has the details.
For code in `web/`:

- **The current user:** in a Server Component, `await getCurrentUser()` from `lib/auth/session.ts` returns
  `{ id, name, email, isAdmin }` or null. It reads cookies, so with Cache Components the component that calls it has
  to sit behind a `<Suspense>` boundary, as `SessionHeaderNav` does in `AppShell`. Keep the read out of layouts'
  top level, or the whole page waits for it. Pass this narrow user to Client Components, never the session.
- **Admin-only UI:** use `user.isAdmin` to hide links and controls; `main-nav.tsx`'s Users link is `adminOnly`. The
  API enforces `helix-admin` itself.
- **Calling the API from the browser:** fetch `/api/proxy/<path>`, which goes to `<API_URL>/api/<path>` with the
  user's access token. A signed-out request gets 401. Responses stream, so server-sent events work through it.
  Use `apiFetch` from `lib/api.ts`, and wrap the calls in TanStack Query hooks (`useQuery` to read, `useMutation` and
  invalidate the list's query key to change). The API's errors are problem details; `apiFetch` throws them as an
  `ApiError` whose message is fit for a toast.
- **URL hooks on dynamic routes:** with Cache Components, `usePathname`, `useParams` and `useSearchParams` suspend on
  a route with a dynamic segment, and anything in a layout above it suspends too. Render the component that calls
  them inside a `<Suspense>` boundary whose fallback doesn't call them, as `HeaderNav` does with
  `MainNav` / `MainNavLinks`, or the build fails.
- **Sign in and out:** `signInWithKeycloak` and `signOutEverywhere` in `lib/auth/actions.ts` are server actions.

## Admin: users

`/admin/users` (linked from the main nav for admins only) lets `helix-admin` users invite colleagues by email, and
resend or revoke an invitation. It calls the API's invitation endpoints (see [api.md](api.md#invitations)) through
`/api/proxy/invitations…`.

- **`app/(app)/admin/users/page.tsx`** wraps `UsersAdmin` in `AdminOnly`, behind a `<Suspense>` boundary (`AdminOnly`
  reads the session) with `InvitationsSkeleton` as the fallback.
- **`components/admin/admin-only.tsx`** (`AdminOnly`) reads `getCurrentUser()` and redirects a non-admin, or a
  signed-out visitor, to `/experiments`. This is just UI: the API enforces `helix-admin` on every invitation call
  regardless.
- **`components/admin/users-admin.tsx`** (`UsersAdmin`) renders the invite form above the invitations list, handling
  the list's loading and error states; `InvitationsSkeleton` is also used as the page's `<Suspense>` fallback.
- **`components/admin/invite-form.tsx`** (`InviteForm`) is a `react-hook-form` + zod form (`inviteSchema` in
  `lib/invitations.ts`) with one email field; it clears and toasts on success, and toasts the API's message on
  failure (`ApiError.message`).
- **`components/admin/invitations-table.tsx`** (`InvitationsTable`) is a `@tanstack/react-table` table showing email,
  status (a `Badge`, coloured by status), when it was sent, and when the link expires. Rows whose status is `Pending`
  or `Expired` (`isOpen` in `lib/invitations.ts`) get Resend and Revoke buttons; Revoke asks for confirmation in an
  `AlertDialog` first, since it disables the invited user's Keycloak account.
- **`components/admin/use-invitations.ts`** wraps `lib/invitations.ts` in TanStack Query: `useInvitations` for the
  list, `useInvitationMutations` for invite/resend/revoke, each invalidating the list's query key on settle.
- **`lib/invitations.ts`** has the `Invitation` and `InvitationStatus` types, `inviteSchema`, and `listInvitations` /
  `inviteUser` / `resendInvitation` / `revokeInvitation`, which call the proxy directly (not `apiFetch`) so a 403 can
  be turned into "Only admins can manage invitations." before the generic problem-details handling in `lib/api.ts`.

## shadcn components

Installed: alert-dialog, avatar, badge, button, card, dialog, dropdown-menu, field, input, label, scroll-area, select,
separator, skeleton, sonner, table, tabs, textarea and tooltip. Add more with `npx shadcn@latest add <name>` from
`web/`.

Base UI components compose through the `render` prop rather than Radix's `asChild`:

```tsx
<DropdownMenuTrigger render={<Button variant="ghost" size="icon" />}>…</DropdownMenuTrigger>
```
