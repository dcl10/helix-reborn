# Web app

The Next.js frontend in `web/`: a public landing page, sign-in, the signed-in app shell, experiments and the admin
Users page.

## Running it

To run it in Docker with the rest of the app, see [local-development.md](local-development.md); the image is built by
`web/Dockerfile`. To work on it, from `web/`, with Node 22 and Corepack enabled (`corepack enable`), so you get the npm
version pinned in `package.json`:

Copy `.env.example` to `.env.local` and fill in `AUTH_SECRET` and `AUTH_KEYCLOAK_SECRET` first (see
[auth-setup.md](auth-setup.md#client-secrets)). The landing page, sign-in and `/api/health` work without the API or
Keycloak; everything else needs Keycloak (`docker compose up -d` from the repo root) and, for anything that calls the
API, the API too.

```bash
npm install          # also installs the Husky pre-commit hook
npm run dev          # http://localhost:3000
npm run lint         # ESLint, including Prettier and import order
npm run format       # Prettier --write
npm test             # Vitest, once
npm run build        # production build to .next/standalone
```

The pre-commit hook runs `lint-staged`: `eslint --fix` on staged TS/JS files and Prettier on JSON, CSS and Markdown.

## Public pages

`/`, `/sign-in` and `/api/health` are reachable without a session (`PUBLIC_PATHS` in `lib/auth/authorized.ts`).
`proxy.ts`'s matcher also excludes `api/auth` and static assets, so Auth.js's own endpoints and the health check never
hit the `authorized` callback. Every other page redirects a signed-out visitor to `/sign-in`; `/api/proxy/*` answers
401 instead.

The landing page (`app/page.tsx`) reads the session with `auth()` inside a `<Suspense>` boundary (required with
`cacheComponents`) and redirects a signed-in visitor to `/experiments`; otherwise it renders a hero with a "Sign in"
button that posts to the same `signInWithKeycloak` server action as `/sign-in`.

`GET /api/health` always answers 200 with `{ status: "ok", version, api }`: `version` comes from `HELIX_VERSION`
(`"dev"` when unset), and `api` is the API's own `/health` response (fetched with a 3 second timeout) or `null` when
the API is unreachable. The deploy workflow (#44) polls it through the public URL and compares `version` and
`api.version` against the image it just deployed.

## Sign-in and the session

Auth.js v5 signs users in with Keycloak; [auth-setup.md](auth-setup.md#client-settings) has the details.
For code in `web/`:

- **The current user:** in a Server Component, `await getCurrentUser()` from `lib/auth/session.ts` returns
  `{ id, name, email, isAdmin }` or null. It reads cookies, so with Cache Components the component that calls it has
  to sit behind a `<Suspense>` boundary, as `SessionHeaderNav` does in `AppShell`. Keep the read out of layouts'
  top level, or the whole page waits for it. Pass this narrow user to Client Components, never the session.
- **Admin-only UI:** use `user.isAdmin` to hide links and controls; `main-nav.tsx`'s Users link is `adminOnly`. The
  API enforces `helix-admin` itself.
- **Calling the API from the browser:** fetch `/api/proxy/<path>`, which goes to `<API_URL>/api/<path>` with the
  user's access token. A signed-out request gets 401. Responses stream, so server-sent events work through it.
  Use `apiFetch` from `lib/api.ts`, and wrap the calls in TanStack Query hooks (`useQuery` to read, `useMutation` and
  invalidate the list's query key to change). The API's errors are problem details; `apiFetch` throws them as an
  `ApiError` whose message is fit for a toast.
- **URL hooks on dynamic routes:** with Cache Components, `usePathname`, `useParams` and `useSearchParams` suspend on
  a route with a dynamic segment, and anything in a layout above it suspends too. Render the component that calls
  them inside a `<Suspense>` boundary whose fallback doesn't call them, as `HeaderNav` does with
  `MainNav` / `MainNavLinks`, or the build fails.
- **Sign in and out:** `signInWithKeycloak` and `signOutEverywhere` in `lib/auth/actions.ts` are server actions.

## Experiments

`/experiments` lists the caller's experiments and lets them create one; each experiment then lives at
`/experiments/[id]` with a tab layout. It calls the API's experiment and dataset endpoints (see
[api.md](api.md#experiments-and-datasets)) through `/api/proxy/experiments…`.

- **`app/(app)/experiments/page.tsx`** renders the list (`ExperimentsTable`) and a "New experiment" button
  (`NewExperimentDialog`); creating one navigates to its Data tab.
- **`app/(app)/experiments/[id]/layout.tsx`** awaits `params` behind a `<Suspense>` boundary and renders
  `ExperimentHeader`, above `children` (the active tab).
- **`app/(app)/experiments/[id]/page.tsx`** redirects to the Data tab; #38 replaces this with an overview.
- **`app/(app)/experiments/[id]/data/page.tsx`** renders `DatasetOverview`, **`eda/page.tsx`** the EDA tab
  ([below](#eda-tab)) and **`pipelines/…`** the Pipelines tab ([below](#pipelines)). The other four tab pages (`runs`,
  `evaluations`, `predict`, `files`) are "Coming soon" placeholders until their own issues (#27, #35, #37, #38) build
  them out.
- **`components/experiments/experiment-header.tsx`** (`ExperimentHeader`) shows the experiment's name and
  description, `EditExperimentDialog` (PATCH) and `DeleteExperimentButton` (an `AlertDialog` confirm, then
  DELETE and navigate back to `/experiments`), and the tab navigation below them.
- **`components/experiments/experiment-tabs.tsx`** (`ExperimentTabs` / `ExperimentTabLinks`) links to each
  tab (Data, EDA, Pipelines, Runs, Evaluations, Predict, Files) and highlights the one `pathname` starts
  with. `ExperimentTabs` reads `usePathname()`, so it suspends on this dynamic route: render it inside a
  `<Suspense>` boundary whose fallback is `ExperimentTabLinks` with no `pathname`, as `main-nav.tsx` does
  for the main nav.
- **`components/experiments/dataset-overview.tsx`** (`DatasetOverview`) is the Data tab: `DatasetUpload`
  when the experiment has no dataset yet, or a summary (file name, size, rows, columns) and
  `DatasetColumnsTable` (name, a type badge, missing count) once it does.
- **`components/experiments/dataset-upload.tsx`** (`DatasetUpload`) is a drop zone plus file input
  accepting `.csv`, rejecting anything over 50 MB client-side before it ever reaches the API's own limit.
  While uploading it disables the button and shows "Uploading…"; the API's error message (409 already has
  a dataset, 400 invalid CSV, 413 too large) surfaces as-is.
- **`components/experiments/use-experiments.ts`** wraps `lib/experiments.ts` in TanStack Query:
  `useExperiments` / `useExperiment` / `useDataset` to read, and mutations for create, update, delete and
  dataset upload, each invalidating the relevant query key on success.
- **`lib/experiments.ts`** has the `Experiment`, `Dataset` and `DatasetColumn` types, `experimentSchema`,
  `experimentPath`, `MAX_DATASET_BYTES`, and the calls to `/api/proxy/experiments…`, including
  `uploadDataset`, which sends `FormData` (no `Content-Type`; the browser adds the boundary).

Dataset uploads go through `proxy.ts`, which otherwise buffers request bodies to Next's ~10 MB default;
`next.config.ts` raises this to 50 MB with `experimental.proxyClientMaxBodySize`.

## EDA tab

`/experiments/[id]/eda` explores the experiment's dataset through the API's EDA endpoints
([api.md](api.md#eda)), which call the EDA service. Everything is in `components/eda/`:

- **`eda-tab.tsx`** (`EdaTab`) loads the summary. When the API answers 409 (no dataset) it links to the Data tab;
  otherwise it shows four cards: Summary, Create a plot, Normality tests and Plots.
- **`summary-table.tsx`** (`SummaryTable`) has one row per column: a numeric/text badge, missing (count and %),
  unique, and mean, std, min, median and max to 4 significant figures (`—` where null). A text column's name has a
  tooltip with its top values.
- **`plot-builder.tsx`** (`PlotBuilder`) is one react-hook-form + zod form (`plotSchema` in `lib/eda.ts`) holding
  every plot type's fields, so switching type keeps what was entered. It shows only the chosen type's fields:
  target column, bins and KDE for a target distribution; numeric columns, method and annotate for a correlation
  heatmap; 2–10 numeric columns, hue, corner and diagonal for a pairplot; numeric columns, colour column and scaling
  for PCA, plus perplexity for t-SNE. The limits are the EDA service's own. `toPlotRequest` sends only the chosen
  type's fields, in snake_case, with an empty column list or choice as `null` ("all numeric columns" / "none").
  Generate shows a spinner and "This can take up to a minute"; the API's error (EDA's own message) shows inline.
- **`plot-options-form.tsx`** (`PlotOptionsForm`) is the builder's collapsible "Plot options": title, style, colour
  map, size, DPI, fonts and label rotation. Empty fields are left out so EDA's defaults apply. The keys are
  snake_case (`title_font_size`): the API passes `plotOptions` to EDA as-is, and EDA rejects unknown keys.
- **`form-fields.tsx`** has the builder's field helpers, each a `Controller` around a shadcn `field`:
  `SelectField` (Base UI `Select` with an `items` map, plus an optional "none" choice stored as `""`),
  `NumberField` (empty means `undefined`), `TextField`, `CheckboxField` and `ColumnChecklist`, the multi-select: a
  list of `checkbox`es in a `scroll-area`, keeping the columns' order.
- **`normality-table.tsx`** (`NormalityTable`) runs the normality tests on every numeric column and shows the
  latest run's results with a ✓/✗ "Normal (p > 0.05)" column. The API also saves each run as a CSV artifact.
- **`plot-gallery.tsx`** (`PlotGallery`) shows the experiment's `edaPlot` artifacts, newest first, as cards with
  the title, the image, when it was made and a download link (`?download=true`). The image opens full size in a
  `dialog`. Images are plain `<img loading="lazy">` from `/api/proxy/…/artifacts/{id}/content`: `next/image` can't
  fetch through the authenticated proxy.
- **`use-eda.ts`** wraps `lib/eda.ts` in TanStack Query: `useEdaSummary` (409 becomes `null`), `useEdaArtifacts`,
  and the `useCreatePlot` and `useRunNormalityTests` mutations, which refresh the artifacts and never retry
  (`retry: false`): a plot can take a minute, and a bad request won't change on retry.
- **`lib/eda.ts`** has the summary, artifact, plot and normality types (EDA's are snake_case, passed through by
  the API), `plotSchema`, `toPlotRequest`, `artifactContentUrl` and the calls to `/api/proxy/experiments/{id}/eda/…`.

## Pipelines

The Pipelines tab (`/experiments/[id]/pipelines`) lists the experiment's saved pipelines. Users build one in an editor
without writing code. Every step and its settings come from the pipeline catalog (`GET /api/pipeline-catalog`, generated
from helix-core, see [pipelines.md](pipelines.md#the-catalog)), so the forms are generated from each step's JSON Schema.
Only the scaler warning below names step ids. The API calls are in [api.md](api.md#pipelines).

- **Pages:** `pipelines/page.tsx` (`PipelinesList`), `pipelines/new/page.tsx` (`PipelineEditor`) and
  `pipelines/[pipelineId]/page.tsx` (`EditPipeline`, which loads the pipeline into the editor). Each awaits `params` in
  a `<Suspense>` boundary, like the other tabs.
- **`pipelines-list.tsx`** (`PipelinesList`): name (links to the editor), model label, feature count and last update,
  with edit, and delete behind an `alert-dialog` confirm (runs keep their own copy of the spec). The Run button slot is
  for #27.
- **`pipeline-editor.tsx`** (`PipelineEditor`): one react-hook-form + zod form in cards:
  - Name.
  - Problem and data:
    - problem type (`radio-group`)
    - target column (any column)
    - optional ID column
    - feature checkboxes: every numeric column other than the target and ID, all ticked to start; text columns are
      listed disabled as "(not numeric)"
    - choosing a column as the target or ID removes it from the features
  - Split: test size, random seed, cross-validation folds (off or 2–10).
  - Steps (`StepList`).
  - Model: the catalog's models for the problem type, then its params.
  - Hyperparameter search (`SearchSettings`).

  Changing the problem type drops the steps and model that don't support the new one, with a toast saying what went.
  Saving POSTs (or PUTs) and returns to the list. The API's `errors.spec` messages show in an `alert` at the top. The
  editor needs the dataset's columns, so without a dataset it links to the Data tab.
- **`step-list.tsx`** (`StepList`): the ordered preprocessing and feature-selection steps (`useFieldArray`).
  - An "Add step" `dropdown-menu` lists the catalog's preprocessors and feature selectors for the problem type, grouped
    by kind. An added step starts with its defaults.
  - Each step shows its label, its description, its params form, and move up / move down / remove buttons.
- **`step-params-form.tsx`** (`StepParamsForm`): a step's params, generated from its `params_schema` by
  `lib/json-schema-form.ts`:
  - a text input per number (a blank nullable one means None), a checkbox per boolean, a select per enum, and a
    comma-separated input per int list (`100, 50`)
  - the field's description and limits (e.g. "10 to 1000") as help text
- **`search-settings.tsx`** (`SearchSettings`): an optional `switch`. Then the method (grid or random), CV folds, and
  for random the number of combinations to try.
  - The grid starts as the model's default `search_grid`, shown read-only as badges.
  - "Customise" turns it into a text field per param: comma-separated candidates (`None` allowed for a nullable param),
    or `;`-separated lists for an int list param (`50; 100, 50`). Each candidate is checked against the param's schema.
  - A model with no default grid must be customised.
- **The scaler warning:** a non-blocking `alert` under the model when a scaler comes before a tree model with nothing
  scale-sensitive in between: "Tree models don't need scaling, so Min-max scaling has no effect on this model…".
  `redundantScalerSteps` in `lib/pipelines.ts` mirrors `helix_core.pipelines.redundant_scaler_steps` (the training
  worker uses it to explain a failed parity check), and both are tested against the same cases.
- **`lib/json-schema-form.ts`** supports exactly what pydantic emits for the catalog's params:
  - `integer`, `number` and `boolean`
  - `enum`
  - `anyOf: [X, {type: null}]` (nullable)
  - arrays of integers
  - bounds (`minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `minItems`, `maxItems`)
  - `default`, `title`, `description`
  - local `$ref`s to `#/$defs/…`

  Anything else throws `UnsupportedSchemaError`. `describeFields` turns a schema into field descriptors. `paramsZod`
  validates a step's params as the form holds them (number inputs as text) and outputs the typed snake_case params.
  `paramsToForm` goes the other way. A test runs every step of the real `contracts/pipeline-catalog.json` through all
  of them, so a new catalog step the UI can't render fails CI.
- **`lib/pipelines.ts`:**
  - the catalog and spec types (snake_case, as stored)
  - the fetchers
  - `emptyForm`, `formFromSpec` and `specFromForm`, which converts between the editor's values and the spec and keeps
    features in dataset order
  - `pipelineFormSchema`, the API's rules checked in the browser: columns against the dataset (a regression target
    must be numeric), steps and params against the catalog, and the search settings
  - the grid text helpers
  - `redundantScalerSteps`
- **`use-pipelines.ts`**: `usePipelineCatalog` (cached for the session, `staleTime: Infinity`), `usePipelines`,
  `usePipeline`, `useSavePipeline` (create or update) and `useDeletePipeline`.
- **`lib/api.ts`'s `ApiError`** now keeps a validation problem's `errors`, so the editor can show every message, not
  just the first.

## Admin: users

`/admin/users` (linked from the main nav for admins only) lets `helix-admin` users invite colleagues by email, and
resend or revoke an invitation. It calls the API's invitation endpoints (see [api.md](api.md#invitations)) through
`/api/proxy/invitations…`.

- **`app/(app)/admin/users/page.tsx`** wraps `UsersAdmin` in `AdminOnly`, behind a `<Suspense>` boundary (`AdminOnly`
  reads the session) with `InvitationsSkeleton` as the fallback.
- **`components/admin/admin-only.tsx`** (`AdminOnly`) reads `getCurrentUser()` and redirects a non-admin, or a
  signed-out visitor, to `/experiments`. This is just UI: the API enforces `helix-admin` on every invitation call
  regardless.
- **`components/admin/users-admin.tsx`** (`UsersAdmin`) renders the invite form above the invitations list, handling
  the list's loading and error states; `InvitationsSkeleton` is also used as the page's `<Suspense>` fallback.
- **`components/admin/invite-form.tsx`** (`InviteForm`) is a `react-hook-form` + zod form (`inviteSchema` in
  `lib/invitations.ts`) with one email field; it clears and toasts on success, and toasts the API's message on
  failure (`ApiError.message`).
- **`components/admin/invitations-table.tsx`** (`InvitationsTable`) is a `@tanstack/react-table` table showing email,
  status (a `Badge`, coloured by status), when it was sent, and when the link expires. Rows whose status is `Pending`
  or `Expired` (`isOpen` in `lib/invitations.ts`) get Resend and Revoke buttons; Revoke asks for confirmation in an
  `AlertDialog` first, since it disables the invited user's Keycloak account.
- **`components/admin/use-invitations.ts`** wraps `lib/invitations.ts` in TanStack Query: `useInvitations` for the
  list, `useInvitationMutations` for invite/resend/revoke, each invalidating the list's query key on settle.
- **`lib/invitations.ts`** has the `Invitation` and `InvitationStatus` types, `inviteSchema`, and `listInvitations` /
  `inviteUser` / `resendInvitation` / `revokeInvitation`, which call the proxy directly (not `apiFetch`) so a 403 can
  be turned into "Only admins can manage invitations." before the generic problem-details handling in `lib/api.ts`.

input, label, radio-group, scroll-area, select, separator, skeleton, sonner, switch, table, tabs, textarea and

`web/`.
